## Verification notes from full-text reads

### group a cxl systems

1. **`cxl_intro` Version & Estimates**: The text file contains the tutorial survey preprint (arXiv:2306.11227) subsequently published in *ACM Computing Surveys* 2024 (DOI: 10.1145/3669900). Switched latency numbers (e.g., ~250 ns end-to-end load-to-use, 70 ns switch adder) are author analytical estimates combining Intel SPR timing models and vendor whitepapers, rather than empirical measurements of physical multi-port CXL switches.
2. **`pond` Latency Adders & Stranding Bounds**: The 7% DRAM saving corresponds to a 222% remote latency increase model, whereas a 182% latency increase model achieves 9% savings. Cluster memory stranding in production traces is reported as "up to 25%" in the introduction/abstract, but characterized across individual clusters as ranging from 3% to 27% in Sec. 3.
3. **`tpp` Version & Baseline Discrepancies**: The file contains the arXiv preprint (arXiv:2206.02878v2, May 2023) corresponding to the ASPLOS '23 paper (DOI: 10.1145/3582016.3582063). Reported performance gains vary by application and memory capacity ratio (2:1 vs 1:4 local:remote ratio), with headline figures showing up to 18% improvement over default Linux and 5–17% improvement over NUMA Balancing and AutoTiering.
4. **`directcxl` Text Extraction Artifacts**: The raw text contains character extraction artifacts where `/C2` appears in place of the multiplication symbol `×` (e.g., `7 /C2` represents `7×`, `8.3 /C2` represents `8.3×`, `6.2 /C2` represents `6.2×`, `3 /C2` represents `3×`, `2.2 /C2` represents `2.2×`, and `3.9 /C2` represents `3.9×`). Clock rates are 100 MHz for the softcore RISC-V host cores and 250 MHz for the FPGA CXL/PCIe subsystem IPs.
5. **`case_pool` Cost & Latency Sourcing**: All switch cost projections ($38,500 switch cost, 12.6 TB break-even point) are author economic estimates using high-end Mellanox Ethernet switches as a cost proxy for hypothetical CXL switches. The 280 ns CXL access latency is cited from external measurements of early CXL ASICs by Sun et al. (MICRO '23 / arXiv:2303.15375), not measured directly by the authors.
6. **`my_cxl_pool` Version**: Full text corresponds to the accepted HotOS '25 paper (ACM ISBN 979-8-4007-1475-7/25/05, DOI: 10.1145/3713082.3730393; arXiv:2503.23611v3, April 2025). The prototype relies on multi-headed device (MHD) pods rather than CXL switches; multi-rack switch fabrics and 400 Gbps dual-link operations are author projections for future Intel Xeon 6 platforms.
7. **`hpc_pool` Metric Sensitivity Thresholds**: In the abstract, the authors state that "Three out of seven scientific applications had less than 10% performance impact when the pooled memory backed 75% of their memory footprint," whereas Section I and Section V.B report that "Five out of seven scientific applications can sustain performance with 75% memory footprint backed by the memory pool" with "less than 18% performance degradation." These represent the same benchmark data evaluated at 10% versus 18% degradation cutoffs.

### group b fairness

1. **FAI-CXL Algorithm 2 Prose versus Pseudocode Ambiguities**:
   - **Queue Partitioning and Dispatching (Lines 4–5 vs. Prose)**: The prose in Section IV-C (PDF p. 5) explicitly describes a *"three-tier priority queue (high, buffer, and low) where high-priority hosts are scheduled first, subject to configurable dispatch quotas for bandwidth distribution"*. However, the pseudocode in Algorithm 2 never dispatches `Qbuffer` as an independent tier. Instead, lines 4–5 collapse dispatching into two quota blocks: line 4 dispatches up to $N_{high}$ flits from `Qhigh` and buffer hosts whose $P_{last}[h] = \text{high}$; line 5 dispatches up to $N_{low}$ flits from `Qlow` and buffer hosts whose $P_{last}[h] = \text{low}$.
   - **Transitional State Inversion / Overwrite Bug (Lines 12–13 & 17–18 vs. Prose)**: The prose specifies that *"The buffer tier serves as a transitional state, preserving the previous priority for one window to prevent oscillations and premature priority changes."* However, in line 13, when an under-threshold host ($B[h] < \theta \cdot \text{avg}$) leaves `Qlow`, the algorithm executes `move to Qbuffer; Plast[h] <- high`. Setting $P_{last}[h]$ to `high` immediately causes line 4 to dispatch this host under the $N_{high}$ quota in the current window, instantly promoting its effective priority rather than preserving its previous low priority for one window. Symmetrically, line 18 sets $P_{last}[h] \leftarrow \text{low}$ for demoted hosts, prematurely forcing them into the low quota immediately upon entering `Qbuffer`.
   - **Middle Band / Dead Zone Inaction ($\theta \cdot \text{avg} \le B[h] \le \text{avg}$)**: Algorithm 2 only contains conditional branches for $B[h] < \theta \cdot \text{avg}$ (lines 9–13) and $B[h] > \text{avg}$ (lines 14–18). If a host's bandwidth usage falls strictly in the intermediate zone $[\theta \cdot \text{avg}, \text{avg}]$, neither branch executes. If a host entered `Qbuffer` during a prior window and subsequently consumes intermediate bandwidth, it is never migrated out of `Qbuffer` to `Qhigh` or `Qlow`, leaving it indefinitely stuck in the transitional buffer tier without any timeout, decay, or fallback rule defined in the text or pseudocode.
   - **Quota Values in Evaluation**: While the mechanism defines configurable quotas $N_{high}$ and $N_{low}$, Section V-B.3 (PDF p. 7) configures both $N_{high} = 10$ and $N_{low} = 10$ packets (identical to the RR turn quota of 10 packets), which leaves the priority differentiation dependent solely on queue ordering and quota exhaustion behavior rather than unequal burst allocations.

2. **FAI-CXL Hardware Overhead and Energy Claims (Full-Text Fact vs. Author Estimate)**:
   - In Section VI (PDF p. 8), FAI-CXL states that segment/block metadata requires under 50 KB, LUT under 2 KB, scheduling queues about 100 KB (total storage below 200 KB, $<0.5\%$ of switch SRAM), that LUT lookup and arbitration add $<2\text{ ns}$ to data-path latency, and that energy per useful byte transferred is reduced by an *"estimated 8–12%"*.
   - **Verification status**: These metrics are **unverified author estimates**. The evaluation platform is strictly software-based (ChampSim + Ramulator). The paper presents no RTL source, logic synthesis, cell area reports, static timing analysis (STA), or physical floorplanning to substantiate the 200 KB, $<2\text{ ns}$, or 8–12% claims.

3. **BLISS Synthesis Verification and Power PPA Absence**:
   - BLISS (PDF p. 5, Sec. VI-D; PDF p. 6, Sec. VII-A) provides verified RTL synthesis numbers using Synopsys Design Compiler targeting a commercial 32 nm standard cell library, reporting critical path latency in nanoseconds and cell area in $\mu\text{m}^2$.
   - **Verification status**: BLISS does **not report power dissipation** (neither dynamic nor static leakage power). While timing latency and area complexity are verified from synthesis, full PPA (Power-Performance-Area) cannot be completed from the full text.

4. **CMP Host Memory Controllers vs. Switch Arbitration Isolation**:
   - In STFM, FQMEM, ATLAS, and TCM, the scheduling mechanisms arbitrate commands between processor cores and DRAM banks/channels inside the on-chip processor memory controller. None of these four papers model, evaluate, or isolate switch crossbar arbitration or disaggregated CXL interconnect topologies.
   - Hardware overheads in STFM (1,808 bits, Table 1), ATLAS (8,896 bits, Sec. 5), and TCM ($<4\text{ Kbits}$, Table 2) are pure analytical register bit summations, not post-synthesis gate-level or PPA results.
